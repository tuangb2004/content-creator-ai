# PHẦN 2: CÔNG NGHỆ

## Câu 11: Tại sao chọn ReactJS 19?

**Trả lời:**

Ecosystem và community lớn nhất. Component-based architecture với 49 components tái sử dụng. Virtual DOM cải thiện hiệu suất. Hooks trong React 19 giúp quản lý state dễ dàng. Job market: React được săn đón nhiều. So với Vue: React linh hoạt hơn. So với Angular: React nhẹ và dễ hơn.

---

## Câu 12: Firebase? Tại sao chọn Firebase?

**Trả lời:**

Firebase là PaaS của Google cung cấp backend services sẵn có. All-in-one: Auth, Firestore, Cloud Functions, Storage, Hosting. Serverless: không cần quản lý server, auto scale. Real-time support cho Inspiration feed. Free tier đủ cho dev. Development nhanh hơn.

---

## Câu 13: Firestore vs Realtime Database?

**Trả lời:**

Realtime Database: tree structure, query limited, scale thủ công. Firestore: collections/documents, compound queries, auto-scaling, operations-focused pricing. Chọn Firestore vì data model phù hợp, query tốt hơn, scale tốt hơn.

---

## Câu 14: Cloud Functions hoạt động?

**Trả lời:**

Functions chạy trên cloud không cần server. Triggers: HTTP, Callable, Auth, Pub/Sub. 19 functions: generateContent, generateVideo, createPaymentLink, payosWebhook, posts, projects, authTrigger... Ưu điểm: pay-per-use, auto-scaling, no server management, built-in auth context.

---

## Câu 15: AI APIs tích hợp?

**Trả lời:**

5 providers: Gemini (text/image, đa năng nhưng đắt), Groq (text, nhanh và miễn phí), Pollination (image, miễn phí), SDXL (image, chất lượng cao), Veo (video, Fast 300 credits, Standard 500 credits). Fallback mechanism khi provider fail.

---

## Câu 16: Rate limiting và quota?

**Trả lời:**

Cloud Functions kiểm tra credits trước khi generation, kiểm tra rate limit. Credit quota: user mới 20 credits miễn phí, text 1-2 credits, SDXL 4 credits, Gemini 8 credits, Veo Fast 300, Veo Standard 500. Veo giới hạn 10 videos/ngày.

---

## Câu 17: Ưu/nhược Serverless?

**Trả lời:**

Ưu: không cần server, auto scale, pay-per-use, nhanh, high availability. Nhược: cold start ~2s (giải quyết bằng loading states), vendor lock-in (abstract qua service layer), debugging khó (detailed logging).

---

## Câu 18: Tailwind CSS ưu điểm?

**Trả lời:**

Rapid development: classes như p-4, text-center. Small bundle size: PurgeCSS loại bỏ unused. Consistency: design system thống nhất. Responsive: prefixes md:, lg:. Dark mode: dark: prefix. Customization: extend trong config.

---

## Câu 19: State management trong React?

**Trả lời:**

React Context cho global: AuthContext, LanguageContext, ThemeContext. useState cho local: form inputs, modal. Firebase real-time listeners cho data thay đổi thường xuyên: projects, posts.

---

## Câu 20: Vite vs Create React App?

**Trả lời:**

Vite: Native ES Modules, dev server instant, HMR cực nhanh. Build: Rollup với code splitting, tree shaking. CRA: bundle toàn bộ khi khởi động, chậm với app lớn. Vite nhanh hơn nhiều.

# PHẦN 3: CƠ SỞ DỮ LIỆU

## Câu 21: Thiết kế Firestore?

**Trả lời:**

4 collections: users (uid, email, credits, plan...), projects (userId, title, type, messages, content...), posts (authorId, title, prompt, mediaUrl, likes...), transactions (userId, amount, credits, status...). Relationships: users→projects/posts/transactions là one-to-many.

---

## Câu 22: NoSQL vs SQL?

**Trả lời:**

SQL: fixed schemas, JOINs, ACID. NoSQL: flexible JSON, denormalized, horizontal scaling. Chọn NoSQL vì flexible schema cho text/image/video projects, real-time cho Inspiration, serverless integration, queries đơn giản.

---

## Câu 23: Denormalization?

**Trả lời:**

Trong NoSQL, denormalize thay vì JOIN. Ví dụ: posts lưu authorName, authorPhotoURL thay vì JOIN users. Khi user update profile, Cloud Function cập nhật tất cả posts của user đó.

---

## Câu 24: Indexing và querying?

**Trả lời:**

Firestore tự động indexes cho single field và equality. Composite indexes cần tạo thủ công cho range queries. Query patterns: get user's projects, get posts by category với pagination, cursor-based với startAfter().

---

## Câu 25: Migrations?

**Trả lời:**

Client-side: kiểm tra version trong app, migrate dần. Cloud Function: chạy một lần migrate toàn bộ. Best practices: backup trước, test trên subset, thêm version field.

---

## Câu 26: Transactions?

**Trả lời:**

Dùng khi cần read/write nhiều documents atomic. Ví dụ: tạo content dùng transaction đồng thời trừ credits và lưu project. Dùng atomic increment cho likes count tránh race conditions.

---

## Câu 27: Firebase Storage?

**Trả lời:**

Lưu trữ: AI-generated images/videos, user uploaded files. Cấu trúc: avatars, uploads, generated, inspiration. Security: chỉ owner đọc/ghi generated, inspiration public read.

---

## Câu 28: Caching?

**Trả lời:**

Firestore: enable persistence. React state: cache AI responses. Browser: Vercel CDN cache static files. Image: browser tự cache. Tương lai: React Query, Service Workers.

---

## Câu 29: Backup và disaster recovery?

**Trả lời:**

Firebase scheduled backups cho paid plans. Export data sang JSON lưu GCS. Dùng firebase firestore:export và :import. Backup định kỳ, test restore.

---

## Câu 30: Data retention?

**Trả lời:**

User data: giữ vô thời hạn khi active, xóa khi yêu cầu. Generated content: giữ đến khi user xóa. Transactions: giữ 7 năm. Cleanup: Cloud Function weekly xóa projects cũ >30 ngày.

---

# PHẦN 4: KIỂM THỬ

## Câu 31: Chiến lược kiểm thử?

**Trả lời:**

Manual testing: user flows, multi-browser, responsive, edge cases. Unit testing: nên test Cloud Functions, components nhưng chưa đầy đủ. Integration: API, Firebase, Payment. Performance: Lighthouse, API response times. Security: Firestore rules, auth flows. Hạn chế: automated tests chưa đầy đủ.

---

## Câu 32: Các loại kiểm thử?

**Trả lời:**

Unit Test: test từng function riêng lẻ, cách ly dependencies bằng mock, nhanh, tập trung logic nhỏ nhất. Integration Test: test nhiều components cùng nhau, dependencies thật, chậm hơn, tập trung interaction. E2E Test: test toàn bộ flow, browser thật, chậm nhất, tập trung user journeys.

---

## Câu 33: TDD?

**Trả lời:**

Em dùng Test Last: viết code trước, test sau. TDD workflow: Red - viết test thấy fail; Green - viết code pass; Refactor - cải thiện. Ưu: code testable, regression prevention, documentation. Nhược: chậm ban đầu, learning curve, không phù hợp exploratory.

---

## Câu 34: Jest?

**Trả lời:**

Jest là testing framework phổ biến cho JS/TS. Cài jest, ts-jest, firebase-functions-test. Viết test cases với mock Firebase. Ví dụ: test reject khi prompt empty, test reject khi insufficient credits.

---

## Câu 35: Test Cloud Functions?

**Trả lời:**

firebase-functions-test cho phép test locally. Setup: import, mock config, cleanup. Testing HTTP: wrap function, gọi với params. Testing callable: mock auth context. Testing Firestore triggers: tạo snapshot, wrap, gọi.

---

## Câu 36: RTL vs Enzyme?

**Trả lời:**

RTL test như user, query bằng role/text/label. Enzyme test implementation, query bằng component/state. RTL được khuyến khích vì user-facing. Best practices: query by role, không test implementation details, test behavior.

---

## Câu 37: Cypress vs Playwright?

**Trả lời:**

Cypress: Chrome/Firefox/Edge, hạn chế mobile. Playwright: all browsers bao gồm Safari, nhanh hơn, API testing mạnh hơn. Chọn Playwright vì multi-browser tốt hơn, Microsoft backing.

---

## Câu 38: Performance Testing?

**Trả lời:**

Lighthouse: Performance 85 mobile/92 desktop, Accessibility 90/92, Best Practices 95, SEO 90. API Response: generate text 3.2s, image 12s, video request 0.8s, getPosts 0.5s - đều đạt target.

---

## Câu 39: Security Testing?

**Trả lời:**

Authentication: test không cho truy cập khi chưa login. Authorization: test user không truy cập data user khác. Input validation: test sanitize XSS. Firestore rules: test users đọc được own data, không đọc được other user data.

---

## Câu 40: Code Coverage?

**Trả lời:**

Coverage là tỷ lệ code được test: line, branch, function, statement. Mức: 70% good, 80% very good, 90% excellent. Đề xuất: Cloud Functions 80%, Components 70%, Utils 90%. Coverage ≠ Quality.

---

## Câu 41: BDD?

**Trả lời:**

Em chưa dùng BDD nhưng biết: viết tests bằng ngôn ngữ tự nhiên. Gherkin: Feature, Scenario, Given, When, Then. Benefits: readable bởi non-developers, living documentation, focus on behavior.

---

## Câu 42: Test AI outputs?

**Trả lời:**

Thách thức: AI outputs non-deterministic. Chiến lược: validate structure không phải content; check length hợp lý; đảm bảo không error; fuzzy matching; validate URLs.

---

## Câu 43: Snapshot Testing?

**Trả lời:**

Lưu snapshot output, so sánh với future detect changes. Dùng cho: UI components, JSON responses, error messages. Không dùng: dynamic content, AI-generated, large data. Updating: npm test --updateSnapshot.

---

## Câu 44: Mocking?

**Trả lời:**

Thay dependencies thật bằng giả. Jest: jest.fn(), mockReturnValue, mockImplementation, jest.mock(), jest.spyOn(). Ví dụ mock AI API.

---

## Câu 45: CI/CD?

**Trả lời:**

GitHub Actions: test, lint, build. Chạy khi push/PR main. Benefits: catch bugs early, enforce quality, prevent broken code, consistent environment.

---

## Câu 46: Test Pyramid?

**Trả lời:**

Pyramid: Unit 70%, Integration 20%, E2E 10%. Lý do: unit nhanh/rẻ, E2E chậm/đắt/flaky. Dự án: Unit cho Cloud Functions/utilities, Integration cho APIs, E2E cho login/generate/payment.

---

## Câu 47: Regression Testing?

**Trả lời:**

Re-run tests sau thay đổi đảm bảo features cũ không break. Strategies: automated suite cho features quan trọng, tích hợp CI/CD, visual regression. Prevent: viết tests trước fix bugs, feature branches, require passing tests.

---

## Câu 48: Test Environment?

**Trả lời:**

Development: local, firebase emulators, test API keys. Staging: mirror production. Production: live. Firebase Emulators: firebase init emulators, firebase emulators:start. Environment: .env.test.

---

## Câu 49: Load Testing?

**Trả lời:**

Kiểm tra hệ thống dưới tải nặng. Tools: k6 (recommended), Artillery, JMeter. k6: define options với stages, thresholds. Test scenarios: 100 users browsing, 50 generating content, 20 video, spike test.

---

## Câu 50: Debugging?

**Trả lời:**

Đọc error cẩn thận. Console.log tạm. Run single test. Interactive mode. VS Code debugger. Check mocks. Common: async không handle, thiếu awaits, sai assertions.

# PHẦN 8: BỔ SUNG

## Câu 71: Serverless vs Server-based?

**Trả lời:**

Server-based: quản lý server, scale thủ công, fixed cost. Serverless: không cần server, auto scale, pay-per-use, tập code. Phù hợp: traffic không predictable, giảm thời gian dev, free tier đủ.

---

## Câu 72: API keys security?

**Trả lời:**

Environment Variables: lưu .env không commit. Đọc qua functions.config(). KHÔNG: commit, expose frontend, share.

---

## Câu 73: Firestore vs SQL?

**Trả lời:**

Firestore: flexible schema, real-time, queries đơn giản, scalable. SQL: fixed schema, complex JOINs, ACID, reporting. Dự án: Firestore phù hợp.

---

## Câu 74: Nhiều AI providers?

**Trả lời:**

Redundancy: fallback khi down. Different strengths: Groq free/fast, Gemini multimodal, SDXL quality, Veo video. Cost optimization: dùng provider phù hợp. User choice.

---

## Câu 75: Sensitive data?

**Trả lời:**

Passwords: Firebase Auth. Payment: PayOS xử lý. Keys: Cloud Functions env. User data: Firestore rules. Best practices: HTTPS, minimal collection, retention policies.
